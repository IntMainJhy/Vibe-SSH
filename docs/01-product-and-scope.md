# Vibe-SSH 产品与首版范围

## 产品定义

Vibe-SSH 为用户保存并连接自己的服务器，同时向外部 AI 暴露稳定、低开销的操作入口。Agent 接受部署或排障目标后调用本地工具，用户在桌面应用中看到其动作和真实远端输出，并可随时取得输入权。

用户安装客户端即可日常使用 SSH；首次启动自动同步 Skill 和 CLI。逐主机启用 AI 接入后，通过已有 Agent 环境使用；客户端不要求配置另一个模型供应商或聊天服务。

## 用户与主要场景

主要用户是已有 VPS、通过 Vibe Coding 创建 Web 项目的个人开发者和小型团队。首版处理单用户本地工作站，服务器权限由其 SSH 账号决定。

| 场景 | 起点 | 完成标准 |
| --- | --- | --- |
| 首次配置 | 用户有服务器地址和登录资料 | 用户手动保存主机、核对指纹并成功连接 |
| 日常终端 | 已配置主机 | 用户可打开终端、编辑文件、上传下载 |
| AI 部署 | Agent 可读本地项目且主机已授权 | 产物上线，服务和指定 URL 验证通过，结果可追溯 |
| AI 排障 | 用户指定主机与故障现象 | 有证据的诊断；修改操作在授权范围内执行 |
| 人工接管 | Agent 正在某个任务空间内操作 | 该空间内 Agent 的新输入与新任务被拒绝，用户能控制它 |
| 并行使用 | Agent 正在部署 | 用户照常使用自己的终端，双方连接互不占用 |
| 继续任务 | 用户已归还控制权 | Agent 先读取变化后的状态，再决定下一步 |

## 手动添加主机流程

用户选择“添加服务器”，填写资料，点击测试连接。客户端展示地址、端口、账号和主机公钥指纹，由用户核对后建立信任记录。密码和私钥口令进入凭据模块，普通配置只保留凭据引用。

主机保存与 AI 访问授权是两个动作。主机可以只供人工使用。AI 默认只能列出已授权主机，不能通过工具创建未知服务器、修改认证信息或自动接受变更后的公钥。

同名主机返回明确的候选列表，Agent 不能自行任选一个。稳定主机 ID 用于后续调用；改名不改变 ID。

## 桌面工作区

左侧为服务器分组与任务入口，中间为终端或文件标签，右侧按需显示任务步骤和详情。不要加入聊天输入框或模型选择器。

每个任务空间显示主机、发起的 Agent 名称和当前控制权。Agent 的空间与用户自己的终端位于同一个工作区，使用明确标识区分。后台任务结束后保留结果，不能因关闭一个观察标签误杀任务。

普通任务输出区与真实 PTY 终端的交互能力不同，界面须明确区分。没有可接管输入通道的任务，提供观察、中断和在同目录打开终端；不能展示无效的“接管当前终端”动作。

## 部署范围

首版提供两类经验证的 Skill 参考流程：静态网站经本地构建、同步和 Nginx 上线；已有 Docker Compose 项目经同步、构建、启动和健康检查上线。

部署先探测环境，形成具体步骤，再执行。配置检查失败时不重载服务；新版本健康检查失败时保留诊断信息，并在可支持的范围内恢复应用版本。

DNS、云厂商安全组和购买资源由其他工具或用户处理。数据库数据迁移不属于通用应用版本恢复承诺。远端没有必要组件时，安装步骤必须进入本次具体操作范围。

## 质量要求

| ID | 要求 | 验收方式 |

| NFR-007 | 凭据不进入普通配置或调用参数 | 持久文件与日志检查 |
| NFR-008 | 功能声明可追踪到证据 | 需求、验收项和测试结果对应 |

## 后续版本

Windows 与 Linux 桌面、SSH 认证代理、复杂跳板机与代理、更多密钥格式、端口转发、tmux 恢复、更多部署参考流程按后续优先级处理。团队权限、云同步、多设备托管和移动端单独设计。

## 明确排除

首版不实现内置大模型、自主任务调度、云端 SSH 网关、多租户控制平面、Kubernetes 管理平台或自动生产环境巡检。外部 AI 的既有权限与审批仍然有效，Vibe-SSH 授权不能覆盖这些边界。
