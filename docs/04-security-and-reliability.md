# Vibe-SSH 安全与可靠性

## 边界与假设

首版面向用户自己的工作站与服务器。SSH 账号的远端权限仍是最终权限边界。Vibe-SSH 不能阻止已经拥有该系统用户全部本机权限的程序读取其可访问数据，也不能承诺任意命令输出绝不含敏感信息。

本地内核、CLI、桌面渲染进程、外部 Agent 和远端主机之间分别建立能力边界。外部 AI 可以使用已授权的操作能力，不因此获得主机配置管理或凭据导出能力。

## 凭据与信任

- 用户手动录入密码、选择私钥并输入必要口令。
- 普通数据库只保存凭据引用，秘密交给系统凭据存储适配层。
- 系统秘密存储不可用时允许仅本次会话使用，不能静默退回明文保存。
- 首次主机指纹由用户核对；公钥变化后中止连接，不接受 AI 自动确认。
- CLI 参数、事件元数据、测试快照和诊断信息不包含秘密。
- 已知敏感值在输出展示与模型读取前做尽力脱敏，原始日志的访问和保留单独管理。

编码、分段或远端生成的新秘密可能绕过简单脱敏，因此产品不能宣传“模型永远看不到任何秘密”。凭据管理接口本身不提供明文导出能力。

## 本地控制接口

IPC 端点限定当前系统用户，限制帧大小、并发和未完成请求数。端点发现信息不构成授权；AI 请求还要获得范围受限的主机与能力授权。

人工管理操作不在本地套接字协议中，只存在于应用进程内部；套接字上的调用一律按 Agent 处理，因此调用者无法通过声明自己是用户获得人工权限。Agent 报告的名称只用于显示。渲染进程不直接访问原始凭据、Shell 或任意本机文件；通过受控后端桥接完成具体动作。

授权范围至少关联主机和可用能力。用户授权某台主机部署，不自动授权其他主机或无关本地目录。项目同步通过显式源目录和排除规则控制读取范围。

## 接管和并发

接管必须通过内核的写入串行化边界完成。更新控制权、验证请求和向通道提交输入之间不能出现竞态窗口。

租约在接管、交接和归还时更换，旧租约不会恢复生效。等待中的请求在控制权变化时立即返回。租约防的是过期请求，不是 Agent 之间的隔离：同一系统用户下的进程都能读到 Agent 空间的当前租约，这在本机单用户边界内是已知限制。

运行中的进程和输入权分离。人工接管不自动发送 Ctrl+C，不关闭 SSH 连接。中断动作必须记录请求、发送方式和最终可观察结果；请求中断不等于已确认停止。

## 失败处理

| 事件 | 必须保留的事实 | 恢复方式 |
| --- | --- | --- |
| 认证失败 | 已尝试的方法与脱敏错误 | 用户修改资料后显式重试 |
| 连接断开 | 最后输出、任务身份和结果未知 | 重连后检查服务与产物 |
| UI 崩溃 | 内核与任务仍独立运行 | UI 重连读取快照和游标 |
| 应用退出或崩溃 | 无；任务与输出目前只在内存中 | 新实例标识不同，旧标识返回实例不匹配，Agent 重新查证远端 |
| 日志轮换 | 最早可用位置与缺口 | 明确不完整，不能构造完整回放 |
| 文件被其他程序修改 | 读取摘要与当前摘要 | 报冲突，重新读取后决定 |
| 磁盘空间不足 | 未持久成功的状态 | 进入受限模式，停止创建新修改任务 |
| SSH 执行无退出码 | 已收集输出与缺失证据 | 返回未知，不赋值为零 |

客户端进程退出不保证远端进程退出。首版不承诺跨内核重启恢复原 PTY；tmux 或远端持久任务服务属于单独能力。

## 命令与文件安全

SSH 协议传输的是命令字符串，不等同于本地 argv。工作目录、环境变量和文件名按目标 POSIX Shell 的规则处理，包含引号、换行和特殊字符的路径要进入测试矩阵。

通用远端命令执行本来就具有用户账号权限，不能用几条关键词黑名单宣传为可靠沙箱。权限限制、范围授权与明确的人机控制权才是实际边界。

输出和文件内容可能包含要求 Agent 改变行为的文字。Skill 与协议始终把这些内容标记为数据，不依据其内容扩大主机范围、导出凭据或执行额外本机操作。

## 日志、诊断与保留

诊断默认不自动上传。用户导出时选择范围，显示将包含主机标识、命令与输出的提示。诊断包排除凭据和授权材料。

日志设置按任务上限、全局容量和保留期限管理。删除主机时分别说明配置、凭据和历史记录的处理方式，不能因改名或删除观察标签丢失仍在运行的任务。

## 供应链与发布

依赖锁定具体解析版本，保留许可证清单，跟踪 SSH、加密与桌面框架相关通告。没有生产验收证据的功能不能标记为生产就绪。

正式发布前验证安装包来源、macOS 签名与凭据存储身份、Windows 安装与 IPC 权限、升级与数据库迁移，以及卸载后的数据行为。更新机制在启用之前需要独立的签名验证和回退设计。
