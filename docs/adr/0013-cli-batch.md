# ADR 0013 在 CLI 顺序执行部署步骤

一次 `vibe-ssh batch` 接收 1 至 12 个显式步骤。CLI 先完整校验 JSON，随后使用给定租约，或为用户指定且已授权的主机打开一个任务空间。CLI 逐步提交现有的 `run` 和 `put` 请求，调用方进程打包本地文件。内核在每次提交时重新检查同一租约。

只有上一步明确成功，且控制权仍为 Agent，才提交下一步。等待到期、任务结果未知、任务失败或读不到回执时立即停止。CLI 返回任务、记录和游标，Agent 可核实已提交的步骤。归还控制后也需另行安排剩余操作。没有并行写入、自动重试、断点重放或后台批处理服务。

套接字继续使用协议 v2。任务空间、各步任务和输出都由原应用展示与保留。回执省略提交的命令和租约字段。计划输入和每步输出都有预算。

扩展记录使用 v2 的 `deployment_start`、`deployment_step`、`deployment_stop`。CLI 提交有序步骤名称和类型，应用先持久化计划，再在收到每步时持久化提交意图。回执和终态以应用的任务记录为准；用户可以在桌面打开对应的任务。超时、控制权改变或输送中断保留已提交结果和未提交步骤，不重放。原 `run`、`put` 入口仍用于独立任务。旧服务需要升级后才能记录新版 `batch`。
