# ADR 0011 单跳连接与本地端口转发

目标主机可引用一台已保存的直连主机作为跳板。建立目标连接前先验证并认证跳板，再在跳板连接中打开一个 TCP 通道。目标 SSH 握手独立核对指纹；探测目标指纹不发送目标凭据。目标配置通过屏幕确认启用 Agent 后，Agent 可以使用这条既定线路，但不会获得跳板的终端权限。每个空间独占其连接与跳板通道。本切片不支持链式跳板、任意代理命令或第三方网络代理。

个人会话可创建本地转发，绑定 `127.0.0.1`，端口 0 由系统分配。用户显式选择服务器所见的目标地址与端口。每空间最多 8 条规则，每规则最多 16 条活跃连接。停止规则、关闭会话或发现 SSH 断开时关闭监听和活动转发；不恢复、不持久化。Agent 套接字无转发操作，Agent 创建的空间也不能启用转发。

主机资料新增可选 `jump_host`（保存的主机 ID）。旧资料无需迁移；启用后回退到旧版本前应先移除该设置。协议结构不变。

## 2026-11-18 扩展

主机通过现有的 `jump_host` 形成至多四跳的链。解析时拒绝循环、缺失项和超长路线。每一跳和目标先验证各自指纹再认证，新会话在完成握手时重新核对所有沿途配置版本。关闭时由内向外断开。探测目标时先认证所选路线，目标握手只读公钥。旧资料继续使用原有字段。

本地固定转发与动态 SOCKS5 TCP CONNECT 共用每空间 8 条监听、每条 16 个客户端的限制。动态转发使用回环地址，仅在个人会话显式启动，为本地程序提供 `socks5h://127.0.0.1:端口`。主机名由 SSH 服务器解析，客户端握手限时 5 秒。关闭规则或连接后取消活动流。其他 SOCKS 命令、服务端监听与通用代理配置需要独立实现。参考 [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928)。

远端 TCP 转发也使用上述预算。桌面申请服务器监听在 `127.0.0.1`，目标是客户端指定的回环端口。客户端只接受已登记的监听和服务器报告的回环来源，停止时先取消活动转发，再请求服务器取消监听。监听绑定仍受服务端 `GatewayPorts` 设置管理。超时或断线回执不确定时不自动重发。参考 [OpenSSH 服务端配置](https://man.openbsd.org/sshd_config.5#GatewayPorts)。

## 出站代理

在主机表单显式配置 HTTP CONNECT 或 SOCKS5 TCP CONNECT 代理地址与端口。这两种模式适用于无需代理认证的网络，目标 SSH 认证和指纹检查保持原约束。代理只建立 TCP 隧道，探测与连接使用同一路径。单台主机选择直连、已保存 SSH 跳板或网络代理之一。作为第一跳的已保存主机可有自己的代理配置。代理失败时终止连接。

主机资料新增可选 `proxy`。已有资料无需迁移。启用该字段后需清除代理设置才能回退到旧版本。SSH 配置导入继续提供预览，`ProxyCommand` 仍不执行。参考 [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928) 与 [RFC 9110 CONNECT](https://www.rfc-editor.org/rfc/rfc9110.html#name-connect)。
