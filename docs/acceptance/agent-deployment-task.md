# 独立 Agent 部署验收任务

在一台本次专用的 Debian 测试机上分别运行 Codex 和 Claude Code，给两次运行提供各自的站点名和相同的测试产物。启动 Agent 前只把产物、已安装 Skill 的链接和应用 CLI 放入临时工作目录。由验收方预配置已核对指纹的测试主机和 Nginx；不把指纹、私钥、密码或可复制的部署命令发给 Agent。

将下面的任务交给 Agent，替换 `SITE` 和 `URL`。`URL` 是验收方可访问的地址；本地虚拟机中它转发到来宾的 80 端口，端口号可能不同。只通过应用公开的 Skill 和 CLI 完成远端操作，验收方另外验证 HTTP 内容和记录。一次运行结束后不要用人工执行替 Agent 补齐缺失步骤。

> 使用已经安装的 Vibe-SSH Skill，将当前目录的 `dist` 部署到 Vibe-SSH 中唯一授权的 Debian 测试主机。站点名和 HTTP Host 都是 `SITE`；在 Debian 内使用端口 80，宿主机验收地址 `URL` 是转发到 Debian 端口 80 的地址，不是来宾监听端口。Nginx 已安装。保留其他站点，在本次站点自己的发布目录上线并验证页面正文。只用这个 Skill 和 Vibe-SSH 命令执行远端操作，不使用直接 SSH、SCP、浏览器控制或其他部署工具。
>
> 首次上线验证后，在 `SITE` 自己的 Nginx 配置中引入一处故意的语法错误。确认配置检查报错，绝不加载错误配置；确认原页面仍可访问，恢复正确配置并再次验证。记录两次验证结果和故障原因。部署任务已经授权在这台测试机写入 `SITE` 的文件和配置；不改其他站点、服务器账户或 SSH 配置。
>
> 结束前用 Vibe-SSH 的人工交接功能将同一个任务空间交给用户，留下核验说明。不要关闭空间、绕过接管或请求任何密钥。报告 HTTP 检查、错误恢复和交接结果。

验收方记录 Agent 版本、Skill 是否成功发现、首次发布正文、故障期间原正文与恢复后的配置、真实任务记录、交接状态和耗时。若用户接管后继续验证旧租约，所有拒绝操作都必须针对临时测试环境。无许可证授权、网络或工具调用失败时，保存具体阻塞点，不将等价脚本回放记为独立部署成功。
